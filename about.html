The Project

About the Project

Background, objectives, and methodology of the AI & sensor-based irrigation advisory system for sugarcane.

The Problem

Why Sugarcane Irrigation Needs a Rethink

Sugarcane requires 1,500–2,500 mm of water over its crop cycle, making irrigation scheduling critical to yield and sucrose content. Traditional irrigation in most farms is based on fixed schedules or visual judgment, which frequently causes over-irrigation (wasting water and leaching nutrients) or under-irrigation (stressing the crop during sensitive growth stages).


This project addresses that gap using low-cost sensors and an AI advisory layer that reasons about growth stage, soil condition, and weather together.

Goals

Objectives

Real-Time Monitoring

Continuously measure soil moisture, temperature, and humidity across the sugarcane field.

Growth-Stage Awareness

Tailor irrigation thresholds to germination, tillering, grand growth, and maturity stages of sugarcane.

AI-Based Recommendations

Use sensor and weather data to generate irrigate/hold/delay recommendations and estimated water quantity.

Accessible Dashboard

Present recommendations through a simple web interface usable by farmers with minimal technical training.

Approach

Project Methodology

1. Requirement Analysis

Studied sugarcane water requirements at each growth stage and identified the key parameters (soil moisture, temperature, humidity, rainfall) needed for irrigation decisions.

2. Sensor Selection & Design

Selected capacitive soil moisture sensors, DHT22 temperature/humidity sensors, and a microcontroller (ESP32/Arduino) for field data acquisition — detailed on the Sensors & Tech page.

3. AI Advisory Logic

Trained a neural network (scikit-learn MLPClassifier) on a labeled sugarcane irrigation dataset to map sensor readings and crop stage to an irrigation recommendation, reaching 94.6% test accuracy.

4. Web Interface Development

Developed this five-page website — Home, About, Sensors & Tech, AI Advisory demo, and Contact — using HTML, CSS, and JavaScript, with the trained model running entirely client-side.

5. Testing

Verified navigation across all pages, cross-browser rendering, responsive layout on mobile, and that the browser-side model output matched the Python model exactly.

6. Deployment

Registered a project domain/subdomain and hosted the site on GitHub Pages for public access.
